## Định nghĩa

**QHD Bitmask** dùng một số nguyên để biểu diễn **tập hợp** (bit k bật = phần tử
k có trong tập), biến trạng thái "đã chọn tập gì" thành chỉ số mảng. Dùng khi
n ≤ 20–25 (2ⁿ trạng thái) — chặn trên của quay lui thuần mà QHD giải được
O(2ⁿ · n).

Bài kinh điển: **giao việc** — n người, n việc, chi phí `cost[i][j]` khi người i
làm việc j; mỗi người đúng 1 việc, mỗi việc đúng 1 người. Chi phí tối thiểu?

## Input mẫu

| Input | Ý nghĩa |
| ----- | ------- |
| `cost` 4×4: người 0 `[9,2,7,8]`, người 1 `[6,4,3,7]`, người 2 `[5,8,1,8]`, người 3 `[7,6,9,4]` | Chi phí giao từng cặp (người, việc) |

**Output mong đợi:**

```text
Chi phí nhỏ nhất = 13
Phân công: người 0 làm việc 1 (2), người 1 làm việc 0 (6),
           người 2 làm việc 2 (1), người 3 làm việc 3 (4)
```

## Ý tưởng

Gọi `dp[mask]` = chi phí nhỏ nhất khi **các người trong mask** đã có việc (số
bit bật của mask = số việc đã giao). Người chưa giao đầu tiên là người `i =
popcount(mask)`; thử giao mọi việc `j` chưa ai làm:

```text
dp[mask | (1 << j)] = min(dp[mask | (1 << j)], dp[mask] + cost[i][j])
```

Duyệt mask **tăng dần** đảm bảo dp[mask] đã tối ưu trước khi mở rộng:

<MatrixVisualizer algorithm="bitmaskDp" height={250} />

Ba điểm đáng nhớ:

1. **Thứ tự duyệt mask tăng dần** chính là thứ tự "số bit bật tăng dần" — mọi
   chuyển đều đi từ mask nhỏ hơn sang mask lớn hơn ⇒ mỗi trạng thái tính 1 lần.
2. `popcount(mask)` thay bằng **bit thấp nhất chưa bật** (mẹo `c = mask & -mask`)
   cho bản nhanh hơn khi n lớn.
3. Đây chính là hình dạng của **Đường đi Hamilton ngắn nhất** (Held-Karp):
   dp[mask][v] — cựu vô địch độ phức tạp O(2ⁿ·n²) trên đồ thị 20 đỉnh.

## Kết quả (Output)

Ô cuối `dp[15] = 13` — truy vết từ các bước "Ghi giá trị" của ô 15: lần ghi
cuối đến từ mask 12 (người 0, 1 đã có việc) + bật bit 2, tức người 2 làm việc 2
(+1); mask 12 được ghi từ mask 8 + bit 1: người 1 làm việc 0 (+6); mask 8 từ
mask 0 + bit 0: người 0 làm việc 1 (+2); còn người 3 làm việc 3 (+4). Tổng:
2 + 6 + 1 + 4 = **13** — khớp với phân công ở Input mẫu. So với phân công
"tham lam" nhìn có vẻ đẹp (người 0→việc 1, người 1→việc 2, người 2→việc 0,
người 3→việc 3 = 2+3+5+4 = 14) ta thấy QHD tìm được cấu hình tốt hơn 1 đơn vị
— tham lam từng bước không phải lúc nào cũng tối ưu.

## Code mẫu

```cpp
#include <bits/stdc++.h>
using namespace std;

int main() {
    int n = 4;
    int cost[4][4] = {{9,2,7,8},{6,4,3,7},{5,8,1,8},{7,6,9,4}};
    vector<int> dp(1 << n, INT_MAX);
    dp[0] = 0;
    for (int mask = 0; mask < (1 << n); mask++) {
        if (dp[mask] == INT_MAX) continue;
        int i = __builtin_popcount(mask);          // người tiếp theo chưa giao
        for (int j = 0; j < n; j++)
            if (!(mask & (1 << j)))
                dp[mask | (1 << j)] = min(dp[mask | (1 << j)], dp[mask] + cost[i][j]);
    }
    cout << dp[(1 << n) - 1] << '\n';
    return 0;
}
```

```python
cost = [[9,2,7,8],[6,4,3,7],[5,8,1,8],[7,6,9,4]]
n = 4
INF = float('inf')
dp = [INF] * (1 << n)
dp[0] = 0
for mask in range(1 << n):
    if dp[mask] == INF: continue
    i = bin(mask).count('1')
    for j in range(n):
        if not mask & (1 << j):
            dp[mask | (1 << j)] = min(dp[mask | (1 << j)], dp[mask] + cost[i][j])
print(dp[(1 << n) - 1])
```
