## Định nghĩa

**Cây phân đoạn** trả lời truy vấn trên đoạn (tổng, min, max, gcd...) trong
O(log n) đồng thời **cập nhật phần tử** cũng O(log n) — thứ mà mảng cộng dồn
không làm nổi (cập nhật phải dựng lại cả mảng).

Phiên bản **mảng 2n** (iterative, không đệ quy) gọn nhất cho thi:

- Lá nằm ở ô `n..2n-1`: ô `n + i` giữ `a[i]`.
- Nút nội tại `v` (1 ≤ v < n) giữ **hợp của hai con**: `tree[v] = tree[2v] ⊕ tree[2v+1]`.

## Input mẫu

| Input | Ý nghĩa |
| ----- | ------- |
| `n = 8`, mảng `[5, 2, 9, 1, 7, 3, 8, 6]` | Cây phân đoạn quản lý 8 phần tử |
| Truy vấn: tổng `[2..6]` | Trả lời sau khi dựng cây |

**Output mong đợi:**

```text
Tổng a[2..6] = 9 + 1 + 7 + 3 + 8 = 28
```

## Ý tưởng

Dựng cây: chép mảng vào lá, rồi đi **từ nút n-1 về 1** gán cha = tổng hai con.

Truy vấn `[l..r]` (0-indexed): chuyển sang lá `l + n`, `r + n + 1` rồi leo lên:

```text
lo = l + n, hi = r + n + 1
while lo < hi:
    nếu lo lẻ: res += tree[lo]; lo++     // ô trái là con phải — gom rồi nhích
    nếu hi lẻ: hi--;       res += tree[hi]
    lo >>= 1; hi >>= 1                    // leo lên cha
```

Xem minh họa: từng lá được gán giá trị, rồi các nút cha gộp dần — mỗi ô của
mảng 2n là một nút của cây:

Ba điểm đáng nhớ:

1. **Dựng O(n)**, không phải O(n log n) — mỗi nút tính đúng một lần từ dưới lên.
2. **Cập nhật điểm** `a[i] += x`: gán lá `tree[n+i] += x` rồi leo cha `v >>= 1`
   cộng dồn — đúng log n nút.
3. **Lazy propagation** cho cập nhật **đoạn**: bản iterative khó lazy; khi đề
   yêu cầu cập nhật đoạn, chuyển sang bản đệ quy 4·n ô.

## Kết quả (Output)

Cây sau khi dựng — các nút được dùng khi truy vấn `[2..6]` là ô tô đậm ở bước
"Truy vấn":

<MatrixVisualizer algorithm="segmentTree" height={230} />

Đọc kết quả từ trực quan: truy vấn `[2..6]` gom đúng 4 nút, giá trị các nút đó
cộng lại = 9 + 1 + 7 + 3 + 8 = **28**. Vì sao chỉ cần 4 nút mà không phải 5 lá?
Vì nút cha phủ `[4..5]` (giá trị 7 + 3 = 10) đã gộp sẵn hai lá — mỗi truy vấn
chạm tối đa 2·log n nút thay vì cả đoạn.

Nếu truy vấn q lần trên mảng n phần tử: vét cạn O(n·q), cây phân đoạn chỉ
O((n + q) log n) — n = q = 10⁵ là 10¹⁰ so với ~3·10⁶ thao tác.

## Code mẫu

```cpp
#include <bits/stdc++.h>
using namespace std;

int n;
vector<long long> tree_;

void build(vector<long long>& a) {
    tree_.assign(2 * n, 0);
    for (int i = 0; i < n; i++) tree_[n + i] = a[i];   // lá
    for (int v = n - 1; v >= 1; v--)                   // cha = tổng 2 con
        tree_[v] = tree_[2 * v] + tree_[2 * v + 1];
}

long long query(int l, int r) {              // tổng [l..r], 0-indexed
    long long res = 0;
    for (l += n, r += n + 1; l < r; l >>= 1, r >>= 1) {
        if (l & 1) res += tree_[l++];
        if (r & 1) res += tree_[--r];
    }
    return res;
}

void update(int i, long long x) {            // a[i] += x
    for (tree_[i += n] += x; i > 1; i >>= 1) tree_[i >> 1] = tree_[i] + tree_[i ^ 1];
}

int main() {
    n = 8;
    vector<long long> a = {5, 2, 9, 1, 7, 3, 8, 6};
    build(a);
    cout << query(2, 6) << '\n';   // 28
    update(3, 10);                 // a[3]: 1 → 11
    cout << query(2, 6) << '\n';   // 38
    return 0;
}
```

```python
n = 8
a = [5, 2, 9, 1, 7, 3, 8, 6]
tree = [0] * (2 * n)

def build():
    tree[n:] = a
    for v in range(n - 1, 0, -1):
        tree[v] = tree[2 * v] + tree[2 * v + 1]

def query(l, r):                      # tổng [l..r]
    res = 0
    l += n; r += n + 1
    while l < r:
        if l & 1: res += tree[l]; l += 1
        if r & 1: r -= 1; res += tree[r]
        l >>= 1; r >>= 1
    return res

build()
print(query(2, 6))   # 28
```
